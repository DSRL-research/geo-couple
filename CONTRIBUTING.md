# Contributing

## Set-up

```bash
python3 -m venv .venv
.venv/bin/pip install -e ".[learn,viz,dev]"
scripts/get_onelab.sh            # GetDP, for the FEM tests
.venv/bin/pre-commit install     # ruff on every commit
```

## Checks

```bash
.venv/bin/ruff check geocouple tests scripts
.venv/bin/pytest -m "not fem and not solvers and not server"   # what CI runs
.venv/bin/pytest                                                # everything available locally
```

Test markers: `fem` needs GetDP, `solvers` needs FastHenry / FastCap (`scripts/build_fast_solvers.sh`), `server`
needs a remote worker. Tests whose tools are missing are skipped, not failed.

## Rules that keep results reproducible

- **Labels:** any change that alters FEM labels (meshing, solver settings, templates in
  `geocouple/physics/templates/`, the energy formulas) bumps `SIM_VERSION` in `geocouple/data/simulate.py`. The
  cache key includes it, so old samples are re-simulated instead of silently mixed with new ones.
- **Reports:** `docs/reports/*.md` are generated by `geocouple.bench.report_p*` from `runs/`; edit the generator,
  not the Markdown.
- **Seeds:** every stochastic step takes a `seed` (default 0) and records it in its output.
- **Behaviour-preserving changes** (refactors, cleanups) must leave the test suite and the numbers of a quick
  rerun (P0, one dataset sample) unchanged; say how you checked in the pull request.

## Style

Python 3.11+, line length 120, `ruff` (configured in `pyproject.toml`). Library modules use `logging`
(`_LOG = logging.getLogger(__name__)`); only command-line output uses `print`. Public functions get type hints and a
docstring that states units (µm, Ω, nH, fF).
